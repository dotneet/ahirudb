# Development

Everything needed to build, test, and measure ahirudb. For the architecture
and the reasoning behind the design, see [DESIGN.md](DESIGN.md); for what you
can write in a query, see [sql/README.md](sql/README.md).

## Prerequisites

| Tool | Needed for |
|---|---|
| Rust (stable) | building and testing |
| `wasm32-unknown-unknown` target | wasm builds and size measurement |
| [DuckDB CLI](https://duckdb.org/docs/installation/) | SQL end-to-end tests and test-data generation (tests that need it are skipped when absent) |
| Node 18+ | JS host test suite |
| binaryen (`wasm-opt`) | realistic size numbers — without it, sizes are reported unoptimized |
| [twiggy](https://github.com/rustwasm/twiggy) | optional per-function size breakdown |

## Everyday loop

Development and testing run natively; debugging through wasm is inefficient,
so the split is "develop and test natively, measure size on wasm"
(DESIGN.md §12).

```bash
cargo build --workspace
cargo test --workspace
cargo fmt --all --check
cargo clippy --workspace --all-targets
```

The native CLI is the fastest way to poke at a change:

```bash
cargo run -p ahiru-cli -- schema tests/data/basic.parquet
cargo run -p ahiru-cli -- dump tests/data/basic.parquet 10
cargo run -p ahiru-cli -- query tests/data/basic.parquet \
  "SELECT name, count(*) c FROM t GROUP BY name ORDER BY c DESC"
```

Passing multiple files binds them as `t`, `t2`, `t3`, ... so they can be
joined. Joining several files into one table uses the `a.parquet+b.parquet`
shorthand (a convenience for manual checks only). Run `cargo run -p ahiru-cli`
with no arguments for the full usage text.

## Cargo features

`ahiru-core` defaults to `std,csv,jsonl,zstd` for native builds; wasm builds
pass `--no-default-features` and opt back in to exactly what they need.

| Feature | Default | What it adds |
|---|---|---|
| `std` | on | native-only; wasm builds leave it off (`no_std`) |
| `zstd` | on | ZSTD decompression linked into the core (~13 KB) instead of delegated to the host |
| `csv` | on | CSV / TSV reading |
| `jsonl` | on | JSONL / NDJSON / single-document JSON reading |
| `export` | off | `COPY (SELECT ...) TO 'x.csv'/'x.jsonl'` and the `TableSink` API (~10 KB) |
| `export-parquet` | off | the same, writing Parquet (pulls in a Thrift serializer, ~7 KB; implies `export`) |
| `ddl` | off | `CREATE`/`ALTER`/`DROP TABLE`, views — in-memory tables only |
| `dml` | off | `INSERT`/`UPDATE`/`DELETE` (implies `ddl`) |

When touching `crates/ahiru-core`, check the feature combinations that apply
to the change, not just the default one. The write-path features never touch
the read-only `Source` model, and switching them off removes the code from the
binary entirely (DESIGN.md §16).

## Tests

```bash
cargo test --workspace
```

The SQL end-to-end tests (`crates/ahiru-cli/tests/sql_e2e.rs`) **don't
hardcode expected values — the same query is run against DuckDB and the
results are compared.** Hand-written expectations would silently turn a typo
into the spec, and every new query would need its expected output computed by
hand. Using DuckDB as the reference implementation means adding one line adds
one more verified case. On machines without DuckDB installed, those tests are
skipped. Test data under `tests/data/` is generated by
`scripts/gen-testdata.sh`, also via the DuckDB CLI.

JS host tests:

```bash
./scripts/size.sh          # builds target/ahiru-core.wasm
node --test 'js/test/*.test.mjs'
```

Some of these need extra wasm builds (`--features csv,jsonl`, and a
`--no-default-features` build for the ZSTD-delegation fallback path); the
suite builds them automatically and skips what it can't build. See
[js/README.md](../js/README.md) for the details.

## Size budget

```bash
./scripts/size.sh
```

It reports raw and gzip sizes per configuration plus the incremental cost of
adding CSV / JSONL / ZSTD, and with `wasm-opt` and `twiggy` installed, the
optimized size and a function-by-function breakdown.

The 1 MiB gate is judged on the **fully-loaded configuration** — passing only
with a trimmed distribution wouldn't actually enforce the budget. CI runs the
gate as its own job on every PR, because size is a constraint to hold, not a
target to measure at the end (DESIGN.md §11). Adding a dependency requires
attaching the measured size delta to the PR.

## Browser demo

```bash
./scripts/demo.sh
```

Builds `target/ahiru-core-full.wasm` (parquet + csv + jsonl + zstd, matching
the build the JS host tests use), serves `demo/` on `localhost:8787`
(`PORT=... ./scripts/demo.sh` to change it), and opens it. Read-only on
purpose: `ddl`/`dml`/`export` are left out, since the demo showcases querying
files in a tab, not a database console.

## Docs

Documentation and code comments are written in English (see
[CLAUDE.md](../CLAUDE.md)). `js/errors.js` mirrors `Code` and `message()` from
`crates/ahiru-core/src/error.rs` and the two must be updated together — a test
fails if they drift.
